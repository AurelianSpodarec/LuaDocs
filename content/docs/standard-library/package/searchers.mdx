The list of *searchers* — functions that turn a module name into something that can load it.
[`require()`](/docs/standard-library/globals/require) works through this list in order and
stops at the first one to answer with a loader, so changing the list is how a program changes
where modules come from.

<RunnableExample code={`print(#package.searchers)\nprint(type(package.searchers[1]))\n-- Expected output:\n-- 4\n-- function`} />

<Note>
The examples here run against a sandbox shared with the rest of the site, so each one that
changes the list puts it back afterwards and clears whatever record its load left behind. A page
that leaves either in place changes what the next example sees.
</Note>

## Value

A list of plain functions in the numbered positions of an ordinary table, four of them to start
with. Lua reads this field at the moment a search begins rather than holding on to the list it
was given, so both ways of changing it take effect: writing into the table that is already
there, and assigning a different table over the field. What is read has to be a table when the
next search happens — see the Gotchas.

The order is the meaning. The searcher at position `1` is tried first and the rest in ascending
order, and the first to answer with a loader ends the search; nothing further down is consulted,
whatever it might have found.

## What a searcher is handed, and what it hands back

A searcher is called with one argument, the module name, spelled exactly as it was asked for. The
answer it is expected to give takes one of two shapes:

- *It found the module.* It hands back a *loader* — the function that will actually produce the
  module — and a second value alongside it. That second value is passed on to the loader as its
  own second argument, and comes back from `require()` as a second result on the call that did
  the loading, which is how a caller can tell where a module was found. The searchers that read
  from disk use it for the path the
  file was found at; the one that reads
  [`package.preload`](/docs/standard-library/package/preload) has no path to give and hands back
  the fixed string `":preload:"` instead. A searcher of your own may put anything useful there,
  or nothing.
- *It did not find the module.* It hands back a string saying why, or nothing at all where it has
  nothing worth saying. The strings are collected as the search goes on, and where no searcher
  answers they are what the failure `require()` raises is built from. That is why a missing
  module produces a report naming the places that were tried.

A string is therefore the answer for *failure*, and a function the answer for *success*. An
answer that is neither — a table, a boolean — ends nothing and explains nothing: the search
moves on to the next position without a word. A number counts as an explanation rather than as
neither, since anywhere a string is expected a number will do.

Nothing runs a searcher under protection, so a searcher that raises stops the whole call rather
than being passed over. A searcher is therefore best written to raise nothing and to change
nothing in Lua while it runs, and to report trouble by handing back the explanation as a string.

## The four Lua starts with

Lua fills the list with four: loaders registered by hand, Lua files through
[`package.path`](/docs/standard-library/package/path), C libraries through
[`package.cpath`](/docs/standard-library/package/cpath), and one C library holding several
submodules. What each of them does with the name it is given is set out under
[How a module is found](/docs/standard-library/globals/require#how-a-module-is-found).

Those four are ordinary values in an ordinary table, so none of them is privileged. A program
may add to the list, insert ahead of one, take one out, or replace the lot — and a program left
with the first alone has an interpreter that loads only what has been registered for it.

<Note>
This list was once reached under the name
[`package.loaders`](/docs/standard-library/package/loaders). The two names are one table under
two spellings rather than two lists that resemble each other, so code carrying the old name wants
the new one put in its place — with one thing worth re-reading while it is being changed, because
what a searcher hands back on success grew a second value. The older shape is set out there.
</Note>

## Examples

### Adding a searcher of your own

<RunnableExample code={`local built_in_modules = {\n  package_searchers_example_colours = "return { warning = 'amber' }",\n}\n\ntable.insert(package.searchers, function(module_name)\n  local source = built_in_modules[module_name]\n  if not source then\n    return "not built into this program"\n  end\n  return assert(load(source, module_name)), "built in"\nend)\n\nprint(require("package_searchers_example_colours").warning)\n\ntable.remove(package.searchers)\npackage.loaded["package_searchers_example_colours"] = nil\nprint(#package.searchers)\n-- Expected output:\n-- amber\n-- 4`} />

The searcher compiles the module's source into a function and hands that function back as the
loader, which is what the searchers reading from disk do with the file they find. Added at the
end, it is reached only after the four Lua supplied have all declined.

### The order decides who wins

<RunnableExample code={`local module_path = "package_searchers_example_tariff.lua"\nlocal module_file = assert(io.open(module_path, "w"))\nmodule_file:write("return { source = 'the file on the path' }")\nmodule_file:close()\n\nprint(require("package_searchers_example_tariff").source)\npackage.loaded["package_searchers_example_tariff"] = nil\n\ntable.insert(package.searchers, 1, function(module_name)\n  if module_name ~= "package_searchers_example_tariff" then\n    return "not one of ours"\n  end\n  return function() return { source = "the searcher in front" } end, "ahead of the path"\nend)\n\nprint(require("package_searchers_example_tariff").source)\n\ntable.remove(package.searchers, 1)\npackage.loaded["package_searchers_example_tariff"] = nil\nos.remove(module_path)\nprint(#package.searchers)\n-- Expected output:\n-- the file on the path\n-- the searcher in front\n-- 4`} />

The same name, asked for twice, answered by two different things. Inserting at position `1` puts
the new searcher ahead of everything Lua supplied, so the file that answered the first time is
not even opened the second.

### A searcher that answers with an explanation stops nothing

<RunnableExample code={`local asked_for = {}\n\ntable.insert(package.searchers, 1, function(module_name)\n  asked_for[#asked_for + 1] = module_name\n  return "this searcher never finds anything"\nend)\n\nlocal module_path = "package_searchers_example_invoices.lua"\nlocal module_file = assert(io.open(module_path, "w"))\nmodule_file:write("return { total = 0 }")\nmodule_file:close()\n\nprint(require("package_searchers_example_invoices").total)\nprint(asked_for[1])\n\ntable.remove(package.searchers, 1)\npackage.loaded["package_searchers_example_invoices"] = nil\nos.remove(module_path)\n-- Expected output:\n-- 0\n-- package_searchers_example_invoices`} />

The searcher in front was asked, said its piece and was passed over; the module still came from
the file. A string is not a refusal that ends anything — it is a line that would have appeared in
the report had nothing else answered.

## Gotchas

<Gotcha title="A searcher that raises takes the whole call with it">
Nothing catches what a searcher raises, so one that reads a file, opens a socket or indexes
something that turned out to be `nil` reports that failure as the failure of the `require()` that
happened to run it — and the searchers behind it are never asked. A searcher that can fail should
be written to hand back a string instead, which puts the reason in the report and lets the search
carry on.
</Gotcha>

<Gotcha title="A list that is not a table is only noticed at the next search">
Assigning a number, a string or `nil` over this field is accepted at the moment it happens,
because nothing is watching. The complaint arrives from the next `require()` that has to search,
which may be somewhere else entirely and long afterwards. A list that is a table but empty is
quieter still: every call that has to search fails, and the report it raises has nothing in it,
because there was no searcher to explain anything.
</Gotcha>

<Gotcha title="Changing the list does not reach a module already loaded">
[`package.loaded`](/docs/standard-library/package/loaded) is consulted before any searcher is,
so a module the record already counts as loaded comes back from the record and this list is never
read. A searcher added to take over a module has to be added before anything asks for that
module, or the record entry has to be cleared as well.
</Gotcha>
