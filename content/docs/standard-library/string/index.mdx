Everything Lua does to text on its own is here: finding a substring, cutting one out,
matching a pattern, formatting values into a template, and reading or writing runs of
raw bytes. The functions live in the table `string`, and Lua also gives every string a
metatable whose `__index` is that same table — so `string.upper(text)` can equally be
written `text:upper()`. The entries in this section quote the `string.…` form, which is
the one the manual documents; the example below is written the other way.

Positions are counted in bytes from 1, not 0, and a negative position counts backwards
from the end: `-1` is the last byte, `-2` the one before it. What a function does with a
position landing outside the string is not one rule for the whole library, though:
[`string.sub()`](/docs/standard-library/string/sub) documents how it corrects a *range*,
and the functions taking a place to start searching or reading each state their own reach.

<RunnableExample code={`local product_name = "cocoa powder"\nprint(product_name:upper())\nprint(product_name:sub(-6))\nprint(product_name)\n-- Expected output:\n-- COCOA POWDER\n-- powder\n-- cocoa powder`} />

Nothing here edits a string in place. Every function that looks like it changes one
hands back a new string, which is why the third line still reads as it did.

<Note>
The library assumes one-byte character encodings: lengths, positions and ranges are all
counted in bytes, and a character written in more than one byte is simply several of
them. Nothing here decodes text. Reading and indexing UTF-8 by character belongs to a
separate library, [`utf8`](/docs/standard-library/utf8), whose own version support says
where you can reach for it.
</Note>

## Searching and matching

Four functions look for text described by a *pattern* — Lua's own notation, smaller than
regular expressions — and all four read the same one.

- [Patterns](/docs/standard-library/string/patterns) — the notation the four below take
- [`string.find()`](/docs/standard-library/string/find) — where a match starts and ends
- [`string.match()`](/docs/standard-library/string/match) — the captured parts of the first match
- [`string.gmatch()`](/docs/standard-library/string/gmatch) — an iterator over every match in turn
- [`string.gsub()`](/docs/standard-library/string/gsub) — a copy with every match replaced

## Measuring and cutting

Taking a string apart without a pattern: how much of it there is, and which part of it
you want.

- [`string.len()`](/docs/standard-library/string/len) — how many bytes a string holds
- [`string.sub()`](/docs/standard-library/string/sub) — the piece lying between two positions

## Building and transforming

Each of these returns a new string built from the one handed in.

- [`string.format()`](/docs/standard-library/string/format) — values inserted into a template
- [`string.rep()`](/docs/standard-library/string/rep) — a string written out several times over
- [`string.lower()`](/docs/standard-library/string/lower) — a copy with its uppercase letters lowered
- [`string.upper()`](/docs/standard-library/string/upper) — a copy with its lowercase letters raised
- [`string.reverse()`](/docs/standard-library/string/reverse) — a copy with its bytes back to front

## Bytes and binary data

Where the library stops treating a string as text and treats it as a run of bytes — byte
codes one at a time, whole records built to a layout you describe, and the compiled form
of a function.

- [`string.byte()`](/docs/standard-library/string/byte) — the numeric codes of a string's bytes
- [`string.char()`](/docs/standard-library/string/char) — a string built from numeric codes
- [Format strings for pack and unpack](/docs/standard-library/string/pack-formats) — the layout notation the three below share
- [`string.pack()`](/docs/standard-library/string/pack) — values written out to a byte layout
- [`string.packsize()`](/docs/standard-library/string/packsize) — how many bytes a layout takes
- [`string.unpack()`](/docs/standard-library/string/unpack) — values read back out of one
- [`string.dump()`](/docs/standard-library/string/dump) — a function's compiled form, as a string
