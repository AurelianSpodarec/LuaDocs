Extracts text. It looks for the earliest match of a pattern and hands back the parts of it
the pattern marked as captures — the fields out of a line, the digits out of a label —
rather than the positions [`string.find()`](/docs/standard-library/string/find) reports.

<RunnableExample code={`local log_line = "2026-08-05 12:04:11 WARN disk almost full"\nlocal hours, minutes, seconds = string.match(log_line, "(%d+):(%d+):(%d+)")\nprint(hours, minutes, seconds)\n-- Expected output: 12\t04\t11`} />

## Syntax

```lua
string.match(s, pattern [, init])
```

<Parameters>
  <Param name="s">The string to search.</Param>
  <Param name="pattern">The [pattern](/docs/standard-library/string/patterns) to match.</Param>
  <Param name="init">Where the search begins, as a position in `s` — [`string.sub()`](/docs/standard-library/string/sub) has how positions are read. Omitted, it begins at the first byte.</Param>
</Parameters>

<Returns>
  <Return type="string or integer">One value per capture in the pattern, in the order the captures open — or, when the pattern captures nothing, the single string the whole pattern matched. `nil` when the pattern matches nowhere. Every value is text, except a position capture, which is a number.</Return>
</Returns>

## Description

What comes back is decided by the pattern, not by the call: parentheses are the instruction
*give me this part*, and a pattern carrying three of them returns three values. A pattern
carrying none returns one — the text the whole thing matched — which is the shorthand that
makes `string.match(line, "%d+")` read like a request for the first number in a line.

That makes the parentheses load-bearing in a way they are not in most notations. Against
the subject `timeout=30`, the pattern `"%a+=%d+"` returns `timeout=30`, `"(%a+)=(%d+)"`
returns `timeout` and `30`, and `"(%a+)=%d+"` returns `timeout` alone. Nothing else in the
call changes.

A failed match gives `nil`, which is falsy, so the call goes straight into an `if` or takes
a default from `or` without a comparison in between. Together with the anchors `^` and `$`
described in [Patterns](/docs/standard-library/string/patterns), that turns the function
into a validator as readily as an extractor: a pattern accounting for the whole subject
either returns it or returns nothing.

## Examples

### One field, with and without a capture

<RunnableExample code={`local config_line = "timeout = 30"\nprint(string.match(config_line, "%d+"))\nprint(string.match(config_line, "(%a+)%s*=%s*(%d+)"))\n-- Expected output:\n-- 30\n-- timeout\t30`} />

### Checking a value against a shape

<RunnableExample code={`local order_code = "AB-1234"\nprint(string.match(order_code, "^%u%u%-%d%d%d%d$"))\nprint(string.match("AB-12", "^%u%u%-%d%d%d%d$"))\n-- Expected output:\n-- AB-1234\n-- nil`} />

The pattern is anchored at both ends, so it describes the entire string and a subject that
merely contains something of that shape is rejected along with one that has nothing of the
sort.

### Falling back when nothing matches

<RunnableExample code={`local request_line = "GET /pricing HTTP/1.1"\nlocal page_path = string.match(request_line, "^GET (%S+)") or "/"\nlocal missing_path = string.match("PING", "^GET (%S+)") or "/"\nprint(page_path)\nprint(missing_path)\n-- Expected output:\n-- /pricing\n-- /`} />

## Gotchas

<Gotcha title="What comes back is text, even when it looks like a number">
A capture is a piece of the subject, so `string.match("port = 8080", "%d+")` returns the
*string* `8080`. Arithmetic hides this — Lua converts the string on the spot, so `+ 1` and
`* 2` behave — but comparison does not, and two strings are compared character by
character. `"9" > "8080"` is true, so a version check or a range test done on the raw
result quietly gives the wrong answer. Put the result through `tonumber()` before comparing
it with anything.
</Gotcha>

<Gotcha title="A blank capture succeeds; a missing one is not returned at all">
Two different nothings come out of this function and they behave nothing alike. A capture
whose quantifier matched zero characters succeeds and returns the empty string, which is
truthy: `string.match("key=", "(%w+)=(%w*)")` gives `key` and `""`, so `if value then`
passes for a field that was there but blank. A pattern that did not match at all returns a
single `nil`, so *every* name on the left becomes `nil` at once, not just the last. Testing
the first name tells you whether the match happened; only a comparison against `""` tells
you whether a field had anything in it.
</Gotcha>
