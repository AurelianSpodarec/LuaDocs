# Case study — how MDN Web Docs is built

*Descriptive research, not a decision. This studies MDN's patterns so LuaDocs can
learn from them; the binding choices live in
[`page-structure.md`](page-structure.md) and the ADRs. Findings gathered from
MDN's own writing-guidelines meta-docs plus the `mdn/content` and
`mdn/browser-compat-data` repositories.*

MDN sorts every page into three purpose categories — **Reference** (organized by
the thing's structure), **Guide** (organized by reader goals), and **Navigation**
(landing/listing pages). A machine-readable `page-type` frontmatter key records
the exact subtype. Six dimensions follow.

---

## 1. Page types & section skeletons

Every page carries a `page-type` key from one controlled vocabulary. The
JavaScript set is our closest analogue: `javascript-function`,
`javascript-instance-method`, `javascript-static-method`,
`javascript-instance-data-property`, `javascript-operator`,
`javascript-statement`, `javascript-language-feature`, `javascript-error`,
`javascript-namespace`, plus generic `guide`, `landing-page`, `listing-page`,
`glossary-definition`.

Key structural facts, verified on real pages:

- **Function / method** (`Array.prototype.map`): intro → **Syntax** (with
  **Parameters**, **Return value**, **Exceptions** as *H3s nested under Syntax*,
  present only when applicable) → **Description** → **Examples** (always plural,
  each under a descriptive H3) → **Specifications** → **Browser compatibility** →
  **See also**.
- **Language construct / operator / keyword** (`extends`): **no Parameters, no
  Return value**. Syntax shows a grammatical form; the weight sits in
  **Description**. Otherwise the same skeleton. This function-vs-construct split is
  the main structural fork.
- **Property** (e.g. `math.pi`-like): has a **Value** section instead of
  Parameters/Return.
- **Class / library hub**: lists the type's members (constructor, methods,
  properties) with one-line summaries and status badges, rather than documenting
  one member.
- **Landing / listing** (`CSS Properties`): short intro + a **grouped index of
  links** to child pages (alphabetical, with special buckets). Generated by macros
  like `{{ListSubpages}}` / `{{SubpagesWithSummaries}}`.
- **Glossary**: one definition, ~a screenful, no examples, links out.

MDN's JS reference has **no per-subtype prose template** — one shared skeleton,
with `page-type` + which-sections-apply expressing the subtype.

## 2. Frontmatter & compatibility data (the most important dimension)

MDN cleanly **separates version data from prose.** The page's frontmatter holds
only a *pointer*; all version facts live in the separate `browser-compat-data`
(BCD) repo.

Frontmatter fields: `title`, `short-title`, `slug`, `page-type` (required);
`status`, `browser-compat`, `spec-urls`, `sidebar` (optional). Crucially,
**`status` is auto-derived from BCD, never hand-edited.**

```yaml
title: AbortController
slug: Web/API/AbortController
page-type: web-api-interface
browser-compat: api.AbortController   # dotted key → BCD JSON path
```

At build time `{{Compat}}` looks up `browser-compat` in BCD and renders the
support matrix; `{{Specifications}}` renders from `spec-urls`. The BCD support
statement per "browser" (for us: per Lua version):

| Field | Meaning |
|---|---|
| `version_added` | when support began (`"5.3"`, `true`, `false`, `"≤5.1"`) |
| `version_removed` | when it was dropped |
| `prefix` / `alternative_name` | shipped under a different/renamed identifier |
| `partial_implementation` | present but behaves differently |
| `flags` | gated behind a compile-time option |
| `notes` | per-version behavioral caveats |

Semantic *changes* are modeled as an **array of support statements + `notes`**,
not a dedicated field — the agent recommends we add an explicit author-friendly
`changed_in` map on top, since Lua's story is dominated by subtle semantic changes
between 5.x releases.

**The dotted key doubles as the JSON path**, so the dataset is self-indexing and
lintable: every page's compat key must resolve to a node, every node should have a
page.

## 3. Callouts & status banners

MDN keeps a **deliberately tiny** callout vocabulary (GFM alerts):

- **`> [!NOTE]`** — neutral supplementary info ("worth knowing")
- **`> [!WARNING]`** — real hazards ("ignoring this hurts you")
- **`> [!CALLOUT]`** — no auto-label; author supplies a custom bold title

It **explicitly rejects** `[!TIP]`, `[!CAUTION]`, `[!IMPORTANT]`. Note-vs-Warning
is about *severity*, not topic.

Separately, **status banners** (page-header) and **inline badges** are
*structured metadata*, driven by BCD, not prose: `{{SeeCompatTable}}`
(Experimental), `{{Deprecated_Header}}`, `{{Non-standard_Header}}`, plus the
**Baseline** widget answering "can I use this yet?". The lesson: **emphasis
callouts (human-judged prose) are a different system from status metadata
(data-driven, version-keyed).**

## 4. Code & runnable examples

- **"Try it"** interactive widget sits right under the intro, before the TOC. As
  of **March 2025** MDN moved these *into the content* — the **same fenced block
  that highlights statically is the source the widget runs**, tagged
  ```` ```js interactive-example ````. One source of truth, no separate repo.
- JS has no output-capture API, so MDN **monkey-patches `console.log`** and
  reformats values itself; convention is an `// Expected output:` comment.
- **Live samples** (`{{EmbedLiveSample}}`) render combined HTML/CSS/JS in a
  **sandboxed iframe** — same thread, so a runaway loop can jank the page.
- Static blocks: required language identifier, automatic **copy button**,
  Prettier-formatted, Prism-highlighted; `example-good`/`example-bad` flags render
  green-check/red-cross.
- **Syntax notation:** JS uses a non-linted `js-nolint` block showing overloads by
  *expansion*, and **deliberately rejects BNF/EBNF** as beginner-hostile. CSS
  auto-generates its formal-syntax box from spec data.
- **Good-example rules:** 15–25 focused lines, self-contained, clarity over
  cleverness, prose-sandwich each example, document expected output.

## 5. Navigation

- **Breadcrumb** at the very top, mirrors the URL hierarchy, **last crumb is plain
  text** (not a link), labels are human titles.
- **"In this article"** TOC: **flat, H2-only**, in a **sticky right rail** on
  desktop, collapsing to the top on mobile.
- **Left sidebar:** contextual quick-links for the current reference area, grouped
  under **collapsible taxonomy categories** (Constructor / Static methods /
  Instance methods…), members **alphabetical**, **active entry highlighted with
  its group expanded**.
- No prev/next pager on reference pages; sibling navigation is via the sidebar and
  "See also." Per-area **index pages** provide full-catalog browse.

## 6. Cross-linking & "See also"

- Link the **first meaningful mention** in prose, at **moderate density** — MDN
  does not re-link every occurrence. **Code blocks are never linked.**
- **Descriptive link text**, sentence case matching the target title, **no leading
  article**, no quotation marks; code terms in backticks inside the link.
- **"See also" is always last**, hand-curated (not generated): **reference →
  guides → tutorials**, internal before external, alphabetical/simple-first within
  a group, optional gloss after a colon, no trailing punctuation.

## Implications for LuaDocs

**A. Adopt a `page-type` key and one shared reference skeleton.** Lua vocabulary:
`lua-function`, `lua-library` (the `string`/`table`/`math` hub), `lua-property`
(`math.pi`, `_VERSION`), `lua-operator`, `lua-statement`, `lua-metamethod`,
`lua-language-feature`, `lua-constant`, plus `guide`, `landing-page`,
`glossary-definition`. The key drives which sections apply.

**B. Nest Parameters / Return values / Errors as H3 under a single Syntax H2**,
use **Errors** where MDN uses Exceptions, keep **Examples plural**, and end every
reference page with a **version block + See also**. Lua's *multiple return values*
make the Return-values section richer than MDN's.

**C. The big one — "Change note" should graduate from a prose callout into
structured, versioned compat data.** Separate the data from the prose exactly like
MDN/BCD: a `lua-compat` frontmatter pointer, all version facts in a versioned JSON
tree with `version_added` / `version_removed` / `changed_in` / `notes` / `status`.
The **Version support** strip, the availability banners, and the sidebar
dim+badge are all *generated from this one source of truth* — and `status`
(deprecated/experimental) becomes computed, not hand-maintained. This is a
refinement of [ADR 0001](../adr/0001-single-canonical-docs-with-version-deltas.md):
deltas that are *availability/behavior facts* live in the compat dataset; deltas
that are *prose or examples* stay inline.

**D. Callout set stays tiny:** **Note**, **Warning**, and **Gotcha** (implemented
as a custom-titled callout à la `[!CALLOUT]`). Gotcha = "you'll be surprised";
Warning = "you'll get hurt." No tip/info/caution proliferation.

**E. Examples: adopt the single-source-block pattern** (```` ```lua runnable ````
both highlights and runs). Our advantages over MDN to lean into: **real `print` /
`io.write` → the output panel** (no console monkey-patching), a **Web-Worker
sandbox** with timeouts (can't freeze the page, unlike MDN's same-thread iframe),
**multiple runnable blocks per page** (we're not limited to one), and a
**per-example version selector** that re-runs the same source against a different
Lua WASM build — turning MDN's static compat table into a *live executable*
compatibility demo. Signatures use a `js-nolint`-style non-linted block, **no
BNF**.

**F. Navigation & linking: copy MDN almost verbatim** — breadcrumb (last crumb
plain), flat H2-only "In this article" TOC (sticky right rail / top on mobile),
taxonomy-grouped collapsible sidebar with alphabetical members and highlighted
active entry, per-library index pages, first-mention-in-prose auto-linking (never
in code), and a last-position curated "See also" with MDN's ordering rules.

**G. Scope guard:** the agents suggested a **LuaJIT** column; per
[ADR 0002](../adr/0002-scope-standard-lua-only.md) LuaJIT is out of scope. Our
"versions" axis is standard Lua **5.1–5.5 only**.
