# Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `/blog` as a working surface in the marketing shell — a second MDX
collection, an index listing posts newest-first, a post page, and two real posts.

**Architecture:** The blog is a second `fumadocs-mdx` collection
(`defineCollections`) beside the existing docs collection, read through its own
`loader()` at `baseUrl: '/blog'`. It renders in the **marketing shell**
(`HomeLayout` + `marketingOptions()` + `Footer`), not the documentation shell — per
[ADR 0007](../adr/0007-documentation-shell.md) the docs navbar holds controls only,
and a blog has no content tree to put in a sidebar. Ordering logic lives in a
macro-free module so it is unit-testable.

**Tech Stack:** fumadocs-mdx 15.2 (macro API), fumadocs-core 16.14 (`loader`),
TanStack Start file routes, Zod 4, Vitest + Testing Library, Tailwind 4.

## Global Constraints

- **All work stays on `dev`.** Never merge, rebase onto, or switch to `main`, and
  never push without asking (CLAUDE.md).
- **Commit style:** `type(scope): summary` — imperative, sentence case, ≤ ~60
  characters, no trailing period. **Never** add a `Co-Authored-By` trailer or any
  "generated by" tag (`docs/conventions/commit-messages.md`).
- **Do not modify `baseOptions()`** in `src/lib/layout.shared.tsx`. The docs layout
  renders it; adding nav links there puts navigation in the documentation navbar,
  which ADR 0007 rule 5 forbids.
- **Tests cannot import macro modules.** `vitest.config.ts` does not load the
  `fumadocsMdx()` plugin, so any module calling `defineDocs`/`defineCollections`
  (`src/lib/source.ts`, and the new `src/blog/source.ts`) will fail to transform
  under Vitest. Pure logic goes in `src/blog/posts.ts`, which imports no macro.
- **Content boundary:** blog posts are editorial and dated — release coverage,
  round-ups, project notes. Task-shaped writing ("split a string", "sort a table")
  belongs in guides, not posts, so the two never compete for the same query
  (`docs/research/surface-expansion.md`).
- **Vocabulary:** use `CONTEXT.md` terms. A blog **post** is not an *entry* — entries
  are reference/guide content under `content/docs`.

## File Structure

| File | Responsibility |
|---|---|
| `content/blog/*.mdx` | The posts. Frontmatter: `title`, `description`, `date`, optional `author`. |
| `src/blog/posts.ts` | Pure, macro-free: the post frontmatter type, `sortPostsByDate`, `formatPostDate`. Unit-tested. |
| `src/blog/source.ts` | The `defineCollections` macro call and the `loader()`. Imported only by routes. |
| `src/blog/PostMeta.tsx` | The dateline shared by the index and the post page. |
| `src/routes/blog/index.tsx` | `/blog` — the list, newest first. |
| `src/routes/blog/$slug.tsx` | `/blog/<slug>` — one post. |
| `src/lib/shared.ts` | Gains `blogRoute`. |
| `src/lib/layout.shared.tsx` | `marketingOptions()` gains the Blog link. |
| `src/marketing/Footer.tsx` | Docs column gains Blog. |
| `vite.config.ts` | `/blog` added to the prerender `pages` list. |
| `tests/blog/posts.test.ts` | Ordering and formatting. |
| `tests/blog/PostMeta.test.tsx` | The dateline renders a machine-readable `<time>`. |

**Why `date` is authored frontmatter when `LastUpdated` argues against authored dates.**
`src/entry/LastUpdated.tsx` derives an entry's date from git precisely because an
authored "last updated" rots the moment someone edits and forgets. A post's
publication date is a different fact: it describes *publication*, not the file, and
it must **not** change when a typo is fixed. Git's mtime would be actively wrong
here. Keep both, and keep them distinct.

- [ ] **Step 3: Write `src/blog/posts.ts`**

```ts
/**
 * Pure helpers for the blog, with no `fumadocs-mdx` macro in sight.
 *
 * `vitest.config.ts` does not load the `fumadocsMdx()` plugin, so a module that calls
 * `defineCollections` cannot be imported from a test. Keeping ordering and formatting
 * here is what makes them testable at all — `src/blog/source.ts` next door is the part
 * only the routes can import.
 */
export interface PostFrontmatter {
  title: string;
  description?: string;
  /** Publication date, `YYYY-MM-DD`. Authored, not derived from git — see the plan. */
  date: string;
  author?: string;
}

/**
 * Newest first.
 *
 * `YYYY-MM-DD` sorts correctly as a string, so no `Date` is constructed: parsing a
 * bare date string is timezone-dependent in ways that can reorder two posts a day
 * apart depending on where the build runs.
 *
 * Same-day posts fall back to title, because a stable order matters more than which
 * of the two wins — an unstable sort would reshuffle the index between builds.
 */
export function sortPostsByDate<T extends { date: string; title: string }>(posts: T[]): T[] {
  return [...posts].sort((a, b) => b.date.localeCompare(a.date) || a.title.localeCompare(b.title));
}

/**
 * `7 August 2026`. Matches how `LastUpdated` renders a date, and for the same reason:
 * `03/08/2026` is two different days depending on who reads it.
 */
export function formatPostDate(date: string): string {
  return new Date(`${date}T00:00:00Z`).toLocaleDateString('en-GB', {
    day: 'numeric',
    month: 'long',
    year: 'numeric',
    timeZone: 'UTC',
  });
}
```

import { loader } from 'fumadocs-core/source';
import { pageSchema } from 'fumadocs-core/source/schema';
import { defineCollections } from 'fumadocs-mdx/macro';
import { z } from 'zod';
import { blogRoute } from '@/lib/shared';

/**
 * The blog's own collection, separate from `defineDocs` in `src/lib/source.ts`.
 *
 * Kept eager (no `async: true`) unlike the docs collection: that one is 292 entries and
 * has to load bodies on demand, this one is a handful of posts, and eager loading means
 * the route can render `post.body` without a `preload()` round trip. Revisit if the blog
 * passes roughly thirty posts.
 *
 * `defineCollections` is a build-time macro, so its arguments must be statically
 * analyzable — the schema is written inline rather than imported, exactly as the docs
 * collection does.
 */
export const blog = defineCollections({
  type: 'doc',
  dir: 'content/blog',
  schema: pageSchema.extend({
    /** Publication date, `YYYY-MM-DD`. Required — an undated post cannot be ordered. */
    date: z.iso.date(),
    author: z.string().optional(),
  }),
});

export const blogSource = loader({
  source: blog.toFumadocsSource(),
  baseUrl: blogRoute,
});
```

import { createFileRoute, Link } from '@tanstack/react-router';
import { HomeLayout } from 'fumadocs-ui/layouts/home';
import { blogSource } from '@/blog/source';
import { sortPostsByDate } from '@/blog/posts';
import { PostMeta } from '@/blog/PostMeta';
import { marketingOptions } from '@/lib/layout.shared';
import { Footer } from '@/marketing/Footer';

export const Route = createFileRoute('/blog/')({
  component: BlogIndex,
  head: () => ({
    meta: [{ title: 'Blog — LuaDocs' }],
  }),
});

/**
 * The blog lives in the marketing shell, not the documentation one: it has no content
 * tree, so there is no sidebar for destinations to live in, and ADR 0007 keeps the
 * documentation navbar to controls. Following a post leaves this shell the same way
 * the landing page does.
 */
function BlogIndex() {
  const posts = sortPostsByDate(
    blogSource.getPages().map((page) => ({
      url: page.url,
      title: page.data.title,
      description: page.data.description,
      date: page.data.date,
      author: page.data.author,
    })),
  );

  return (
    <HomeLayout {...marketingOptions()}>
      <div className="mx-auto w-full max-w-3xl flex-1 px-6 py-16">
        <h1 className="text-3xl font-medium">Blog</h1>
        <p className="mt-3 text-fd-muted-foreground">
          Release coverage, notes on how the site is built, and what changes between Lua
          versions.
        </p>

        {posts.length === 0 ? (
          <p className="mt-12 text-fd-muted-foreground">No posts yet.</p>
        ) : (
          <ul className="mt-12 space-y-10">
            {posts.map((post) => (
              <li key={post.url}>
                <article>
                  <h2 className="text-xl font-medium">
                    <Link to={post.url} className="hover:text-fd-primary">
                      {post.title}
                    </Link>
                  </h2>
                  <div className="mt-1">
                    <PostMeta date={post.date} author={post.author} />
                  </div>
                  {post.description ? (
                    <p className="mt-3 text-fd-muted-foreground">{post.description}</p>
                  ) : null}
                </article>
              </li>
            ))}
          </ul>
        )}
      </div>
      <Footer />
    </HomeLayout>
  );
}
```

- [ ] **Step 1: Write `src/routes/blog/$slug.tsx`**

```tsx
import { createFileRoute, Link, notFound } from '@tanstack/react-router';
import { HomeLayout } from 'fumadocs-ui/layouts/home';
import { blogSource } from '@/blog/source';
import { PostMeta } from '@/blog/PostMeta';
import { marketingOptions } from '@/lib/layout.shared';
import { Footer } from '@/marketing/Footer';
import { useMDXComponents } from '@/components/mdx';

export const Route = createFileRoute('/blog/$slug')({
  component: Post,
  loader: ({ params }) => {
    if (!blogSource.getPage([params.slug])) throw notFound();
    return { slug: params.slug };
  },
});

function Post() {
  const { slug } = Route.useLoaderData();
  const page = blogSource.getPage([slug]);
  if (!page) throw notFound();

  // Eager collection, so the compiled body is available without `preload()`.
  const Body = page.data.body;

  return (
    <HomeLayout {...marketingOptions()}>
      <article className="mx-auto w-full max-w-3xl flex-1 px-6 py-16">
        <h1 className="text-3xl font-medium">{page.data.title}</h1>
        <div className="mt-2">
          <PostMeta date={page.data.date} author={page.data.author} />
        </div>
        <div className="prose mt-10">
          <Body components={useMDXComponents()} />
        </div>
        <p className="mt-16 text-sm">
          <Link to="/blog" className="text-fd-muted-foreground hover:text-fd-primary">
            ← All posts
          </Link>
        </p>
      </article>
      <Footer />
    </HomeLayout>
  );
}
```

## Out of scope

Named so nobody adds them mid-task:

- **RSS/Atom feed.** Wanted eventually; it is its own slice with its own decisions
  (full content or summaries, absolute URLs, where the feed lives).
- **Tags, categories, pagination, author pages.** Two posts do not need taxonomy, and
  an empty tag index is worse than no tags.
- **Search over posts.** The existing search indexes the docs collection; adding a
  second collection to it is a separate change.
- **Blog in the documentation sidebar.** It is not a destination in that shell — see
  `docs/research/surface-expansion.md`.
- **OG images for posts.** `docsImageRoute` exists for docs; the blog equivalent is a
  later slice.
