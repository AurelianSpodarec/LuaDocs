# Commit message convention

LuaDocs follows **MDN's commit style** (verified against `mdn/content` history).

## Format

```
type(scope): summary            (#PR)
```

- **type** — Conventional-Commit type: `feat`, `fix`, `docs`, `chore`, `build`,
  `ci`, `refactor`, `test`, `style`.
- **scope** — optional area in parentheses, e.g. `docs(css)`, `chore(deps)`.
- **summary** — imperative mood, sentence case (capitalized first word), **≤ ~60
  characters**, no trailing period.
- **PR reference** — append `(#123)` at the end; on GitHub this is added
  automatically when a PR is squash-merged. Omit for direct commits with no PR.
- **body** — optional; explain the *why* when non-obvious, wrapped ~72 columns.
- **Never** add a `Co-Authored-By` trailer or any "generated by" tag.

## MDN's mix (what to imitate)

MDN uses the type prefix for tooling/infra and often a **plain imperative title**
for content pages:

- `chore(deps): bump fast-uri from 3.1.2 to 3.1.5 (#44984)`
- `docs(css): remove stale flex-basis warning (#44963)`
- `Add privacy primer (#44877)` — content page, no prefix
- `Remove outdated browser compatibility info about sideways-rl (#44970)`

## This repo's mapping

- **Research / design docs** → `docs: …`
- **Content entries** (Lua reference & guides) → plain imperative title
  (`Add string.format entry`) or `content: …`
- **Site code** → `feat: …` / `fix: …` / `refactor: …`
- **Tooling, deps, CI** → `chore: …` / `build: …` / `ci: …`
